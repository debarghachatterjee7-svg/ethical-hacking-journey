## Lab 2 — File vs Text

Attempted:

```bash
md5sum hello
```

Result:

```text
md5sum: hello: No such file or directory
```

Reason: `hello` was interpreted as a filename.

Correct text hashing:

```bash
echo -n "hello" | md5sum
```

## Lab 3 — Hash Text

```bash
echo -n "hello" | md5sum
```

Result:

```text
5d41402abc4b2a76b9719d911017c592
```

This hashes the bytes for `hello` without a trailing newline.

## Lab 4 — Case Sensitivity

```bash
echo -n "Hello" | md5sum
```

Result:

```text
8b1a9953c4611296a827abf8c47804d7
```

`hello` and `Hello` produce different hashes because their input bytes differ.

## Lab 6 — File Integrity

Created:

```bash
echo "This is my original file." > integrity.txt
```

Original MD5:

```text
b5f7a266584910039cc67e26124e3641
```

Modified:

```bash
echo "Changed!" >> integrity.txt
```

New MD5:

```text
1e770e4ec9aa1c82464f6ef974a2b589
```

Therefore:

```text
Original Hash != Modified Hash
```

The checksum changed because the file contents changed.

## Lab 7 — SHA-256

```bash
sha256sum integrity.txt
```

SHA-256 produced a 64-character hexadecimal digest.

Comparison:

```text
MD5      = 128 bits = 32 hex characters
SHA-256  = 256 bits = 64 hex characters
```

## Lab Questions

### Q1. Why didn't `md5sum hello` hash the word hello?
Because `md5sum` interpreted `hello` as a filename.

### Q2. Why use `echo -n`?
To prevent a trailing newline from becoming part of the hashed data.

### Q3. Why did modifying the file change its checksum?
The input data changed, so the hash changed.

### Q4. What does `|` do?
It sends standard output from one command to standard input of another.

### Q5. What is file hashing useful for?
It can help detect unexpected changes when compared against a trusted reference checksum.

## Security Note

MD5 is used here for education and legacy familiarity. It should not be selected for modern security-critical cryptographic integrity or password-storage designs.
