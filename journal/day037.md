## Concepts Learned

### 1. Positional arguments

```bash
$1
$2
$#
$@
```

These allow a script to accept information from the command line instead of hard-coding every target.

The most important new practical idea was:

```bash
for target in "$@"
```

which lets the script process multiple inputs.

---

### 2. Input validation

```bash
if [ "$#" -eq 0 ]; then
    echo "No file supplied."
    exit 1
fi
```

The script should verify its input before performing work.

This is the beginning of defensive scripting: do not trust assumptions about what the user supplied.

---

### 3. File and permission tests

The audit logic used:

```bash
-e
-f
-d
-r
-w
-x
```

These allow a script to ask questions about filesystem objects.

---

### 4. Bash arithmetic

```bash
count=0
count=$((count + 1))
```

This showed how a script can maintain state while processing multiple objects.

---

### 5. `&&` and `||`

Example:

```bash
[ -r "$target" ] && echo "Readable: Yes" || echo "Readable: No"
```

This is compact conditional execution.

It is useful, but it should remain readable. For complicated logic, a normal `if` block is often easier to debug.

---

## Practical Debugging Lesson

The most important practical mistake today was the mismatch between:

```bash
chmod +x day037.sh
```

and:

```bash
./audit.sh
```

The permission was changed on one file while another file was executed.

### Lesson

Always verify:

```bash
pwd
ls -la
ls -l <script>
file <script>
```

before assuming a permission or execution problem.

This is a good security mindset:

> **Verify the actual object and the actual state before changing anything.**
