## 20. Professor Questions & Answers

### Q1. Why review the source code after completing the project?

**Answer:**  
Because completing the code does not automatically mean the source code has been properly reviewed. A final review helps confirm that the functions, menu, and main program flow remain consistent.

### Q2. Why use functions in this project?

**Answer:**  
Functions separate different features into logical sections. This makes the script easier to understand, maintain, debug, and reuse.

### Q3. Why use a `case` statement for the menu?

**Answer:**  
The `case` statement provides a clear way to connect each user-selected menu option to its corresponding function.

### Q4. What does `uname -r` provide?

**Answer:**  
It provides the running Linux kernel release and is used by the project as part of its OS and kernel information feature.

### Q5. Why does the report remove ANSI colour codes?

**Answer:**  
Terminal colour escape sequences are useful for screen output but are unnecessary inside a plain text report. Removing them keeps the generated report readable.

### Q6. Does the security section prove that the system is secure?

**Answer:**  
No. It performs basic enumeration and permission-related checks. It should not be treated as a complete security audit or vulnerability scanner.
