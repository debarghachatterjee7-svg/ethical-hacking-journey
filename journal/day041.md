## Theory Learned

### 1. What is hashing?

A hash function takes input data and produces a fixed-size output called a hash, digest, or message digest.

```text
DATA
  ↓
HASH FUNCTION
  ↓
FIXED-SIZE DIGEST
```

Inputs can include text, files, images, documents, and programs.

### 2. Hashing vs encryption

Encryption is designed to be reversible with the appropriate key and is primarily used for confidentiality.

```text
PLAINTEXT
   ↓
ENCRYPTION + KEY
   ↓
CIPHERTEXT
   ↓
DECRYPTION + KEY
   ↓
PLAINTEXT
```

Hashing is a one-way transformation intended to provide properties useful for integrity and cryptographic constructions.

**Memory phrase:** Encryption hides; hashing fingerprints.

### 3. MD5 output size

MD5 produces a 128-bit digest.

A hexadecimal character represents 4 bits:

```text
128 ÷ 4 = 32
```

Therefore MD5 is represented as 32 hexadecimal characters.

Example:

```text
5d41402abc4b2a76b9719d911017c592
```

### 4. Important hash properties

- **Deterministic:** same input + same algorithm → same hash.
- **Fixed length:** output size depends on the algorithm.
- **Avalanche effect:** a small input change produces a drastically different-looking output.
- **Preimage resistance:** finding an input corresponding to a given hash should be computationally difficult.
- **Second-preimage resistance:** given one input, finding a different input with the same hash should be difficult.
- **Collision resistance:** finding any two different inputs with the same hash should be difficult.

### 5. Collision

A collision is:

```text
Input A ≠ Input B
but
Hash(A) = Hash(B)
```

Collisions must exist mathematically because the input space is much larger than the finite output space. A secure hash aims to make useful collisions computationally difficult to find.

### 6. MD5 security

MD5 is cryptographically broken. Practical collision attacks have been demonstrated against it. It should not be relied upon for modern security-critical cryptographic applications.

It is still useful to understand because it appears in legacy systems, older software, CTFs, old datasets, and file-identification contexts.

### 7. File integrity

A checksum can be used to detect changes relative to a trusted reference:

```text
FILE
 ↓
HASH
 ↓
REFERENCE CHECKSUM

Later:
FILE
 ↓
HASH
 ↓
COMPARE
```

If the values differ, the data changed or the inputs/process differed.

This does not automatically prove authenticity if an attacker can alter both the file and an untrusted checksum.

## Practical Linux Work

### Hash a file

```bash
md5sum day41_md5.txt
```

### Attempt to hash a filename

```bash
md5sum hello
```

This correctly produced:

```text
md5sum: hello: No such file or directory
```

because `hello` was interpreted as a filename.

### Hash text

```bash
echo -n "hello" | md5sum
```

Result:

```text
5d41402abc4b2a76b9719d911017c592
```

### Why `-n` matters

`echo` normally adds a newline. The newline is part of the data being hashed. `echo -n` prevents that newline.

This demonstrates that hashes operate on actual input bytes, not on what the text merely looks like.

### Input-change experiments

Tested values including:

```text
hello
Hello
hello1
hello!
```

The outputs were different, demonstrating the avalanche effect.

### File-integrity experiment

Created:

```bash
echo "This is my original file." > integrity.txt
```

Initial MD5:

```text
b5f7a266584910039cc67e26124e3641
```

Modified:

```bash
echo "Changed!" >> integrity.txt
```

New MD5:

```text
1e770e4ec9aa1c82464f6ef974a2b589
```

The checksum changed because the file contents changed.

### SHA-256

```bash
sha256sum integrity.txt
```

SHA-256 produces 256 bits, represented by 64 hexadecimal characters.

## Professor Questions & Answers

### Q1. What is hashing?
Hashing is the process of taking input data and passing it through a hash function to produce a fixed-size digest.

### Q2. How is hashing different from encryption?
Encryption is designed to be reversible with the appropriate key and is mainly used for confidentiality. Hashing is designed as a one-way transformation and is used in integrity and other cryptographic constructions.

### Q3. Why does MD5 produce 32 hexadecimal characters?
MD5 produces 128 bits. Each hexadecimal character represents 4 bits, so 128 ÷ 4 = 32.

### Q4. What is a collision?
A collision occurs when two different inputs produce the same hash.

### Q5. Why is MD5 broken?
Practical collision attacks have been demonstrated against MD5, so it no longer provides adequate collision resistance for modern security-critical cryptographic use.

### Q6. Why did the checksum change after modifying the file?
The input data changed, so the hash output changed.

### Q7. Why did `hello` and `Hello` produce different hashes?
They contain different bytes because uppercase and lowercase characters are different.

### Q8. If hashing is one-way, how can attackers sometimes discover passwords?
They can make guesses, calculate hashes for those guesses, and compare them with a stored hash. Weak passwords are therefore still vulnerable.

### Q9. Why isn't SHA-256 alone ideal for password storage?
SHA-256 is a fast general-purpose hash. Password storage should use a dedicated password KDF designed to make guessing expensive, with proper salts and system design.

## Biggest Learning

> A hash is a fingerprint-like representation of data: change the data and the digest changes.

The key mental model is:

```text
DATA → HASH FUNCTION → DIGEST
```

## Aha Moment

The `md5sum hello` error clarified the difference between hashing a file and hashing text.

- `md5sum filename` hashes a file.
- `echo -n "text" | md5sum` sends text to the hash program.
