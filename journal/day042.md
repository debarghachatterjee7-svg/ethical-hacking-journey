## Understanding `uname`

This was an important learning point because `uname` should be understood rather than used as unexplained code.

```bash
uname
```

Provides the system/kernel name.

```bash
uname -r
```

Provides the kernel release.

```bash
uname -m
```

Provides the machine architecture.

```bash
uname -a
```

Provides a broader collection of system information.

Memory model:

```text
uname
 ├── -r → release
 ├── -m → machine
 └── -a → all
```

# 🧠 Important Learning: Commands Must Be Understood

A key improvement to the learning method is:

```text
Learn command
   ↓
Run command manually
   ↓
Understand output
   ↓
Use command in Bash
   ↓
Test module
```

For example, `uname` should not simply be memorized as a command that gives kernel information.

The options have specific meanings:

```text
-r → release
-m → machine
-a → all
```

This approach will be followed for future commands.

# ❓ Professor Questions and Answers

### Q1. Why use `#!/bin/bash`?

It specifies Bash as the interpreter for the script.

### Q2. Why use a `while` loop?

The menu needs to repeat until the user selects Exit.

### Q3. Why use `case`?

It provides a clean way to select an action based on the user's menu choice.

### Q4. What does `read` do?

It receives user input and stores it in a variable.

### Q5. What is command substitution?

It captures the output of a command.

Example:

```bash
kernel=$(uname -r)
```

### Q6. What does `uname -r` provide?

The kernel release.

### Q7. What does `uname -m` provide?

The machine architecture.

### Q8. What does `uname -a` provide?

A broader set of system information.

### Q9. What is `$?`?

The exit status of the previous command.

### Q10. What does `chmod +x` do?

Adds executable permission to the script.

### Q11. What does `bash -n` do?

Checks Bash syntax without executing the script.

### Q12. What does `bash -x` do?

Runs the script with execution tracing.

# ⚠️ Correction / Improvement From Today

One thing that became clear today is that commands should be explicitly taught before being treated as known.

For example:

```bash

```

was used in the project, but the command and its options needed explicit explanation.

The improved learning rule is:

> **Never treat an unfamiliar command as "known" just because it appears in project code.**

This will be applied to future modules.
