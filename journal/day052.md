## 29. Professor Questions & Answers

### Q1. What is the overall architecture of the project?

**Answer:**  
It is a Bash dashboard organized into functions, controlled by a repeating menu and a `case` statement that connects user choices to individual functions.

### Q2. Why are functions important?

**Answer:**  
They divide the project into logical features, making the code easier to read, maintain, debug, and reuse.

### Q3. What is the difference between `while` and `for` here?

**Answer:**  
The `while` loop keeps the dashboard running, while the `for` loop is useful for processing a collection of items.

### Q4. Why is `case` useful?

**Answer:**  
It provides a clean way to map different user-input values to different actions.

### Q5. What is command substitution?

**Answer:**  
It allows the output of a command to be captured and used as a value inside the Bash script.

### Q6. Why use pipelines?

**Answer:**  
Pipelines allow multiple commands to work together, with one command's output becoming another command's input.

### Q7. What does `2>/dev/null` do?

**Answer:**  
It redirects standard error to `/dev/null`, preventing that error output from being displayed.

### Q8. Is the security enumeration a complete vulnerability scanner?

**Answer:**  
No. It performs basic enumeration and permission-related checks. It is a learning-focused administrative/security feature rather than a complete security auditing system.
