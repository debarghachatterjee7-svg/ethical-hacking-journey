# What I Learned Today

## 1. Bash Functions

I learned how to create reusable functions:

``` bash
check_file() {
    local target="$1"
    ...
}
```

and call them with different arguments.

This showed me how a script can avoid repeating the same logic.

### Why it matters

A real tool may need to perform the same check on hundreds of files. A
function lets me write the check once and reuse it.

------------------------------------------------------------------------

# 2. Function Arguments

I learned that function arguments are accessed using:

``` bash
$1
$2
$3
```

and that:

``` bash
"$@"
```

can be used to process all supplied arguments individually.

This allowed me to make scripts that accept multiple targets rather than
being hard-coded for one file.

------------------------------------------------------------------------

# 3. File and Permission Auditing

I built a small auditing script that checked:

``` text
Does the target exist?
Is it a regular file?
Is it a directory?
Is it readable?
Is it writable?
Is it executable?
```

The tests used were:

``` bash
-e
-f
-d
-r
-w
-x
```

This was my first practical example of turning Linux filesystem
information into a security-oriented report.

------------------------------------------------------------------------

# 4. Counters and Reporting

I created counters:

``` bash
existing_count=0
missing_count=0
```

and updated them using:

``` bash
$((existing_count + 1))
```

The script eventually produced a summary such as:

``` text
===== Audit Summary =====
Targets checked: 5
Existing: 4
Missing: 1
=========================
```

This taught me that useful automation does not have to dump every raw
result. It can **process information and summarize it**.

------------------------------------------------------------------------

# 5. Debugging

I encountered real errors while building the scripts.

### Permission problem

Initially:

``` text
Permission denied
```

The problem was that the script was not executable.

I fixed it with:

``` bash
chmod +x script.sh
```

### Syntax problem

My first version of `lab4.sh` had a control-flow error involving `else`
and `done`.

The lesson was to carefully match:

``` text
if    ↔ fi
for   ↔ done
```

### Debugging tools

I learned to use:

``` bash
bash -n script.sh
```

for syntax checking and:

``` bash
bash -x script.sh
```

for execution tracing.

This is one of the most practical skills from today's session because
debugging is unavoidable when writing real scripts.

# What Went Wrong Today

The errors were actually useful.

### Error 1

``` text
Permission denied
```

**Cause:** missing execute permission.

**Fix:**

``` bash
chmod +x script.sh
```

### Error 2

``` text
syntax error near unexpected token `else'
```

**Cause:** malformed control-flow structure.

### Error 3

``` text
syntax error near unexpected token `done'
```

**Cause:** the loop/conditional structure was incomplete or incorrectly
arranged.

### What I learned

I should not assume:

> "The code is wrong."

Instead I should ask:

``` text
Is it executable?
Is the syntax valid?
Are the arguments correct?
Are the variables correct?
Is the condition behaving correctly?
Is the path correct?
```

That is a much better debugging mindset.
