# 15. Important Security Lesson

One of the important cybersecurity lessons from this project is:

```text
Finding ≠ Vulnerability
```

For example:

```text
SUID file found
       ≠
Confirmed vulnerability
```

Likewise:

```text
World-writable file found
       ≠
Confirmed security compromise
```

These are enumeration results that require context and further investigation.

The project should therefore describe these features as **enumeration**, rather than claiming that they automatically identify vulnerabilities.

# 31. Professor Questions & Answers

## Q1. Why did you use functions?

**Answer:**  
Functions separate different parts of the project into logical modules. This makes the code easier to understand and maintain.

## Q2. Why use `case` in the dashboard?

**Answer:**  
`case` is well suited for menu-driven programs because each user choice can be mapped directly to a specific action.

## Q3. What does `uname -r` provide?

**Answer:**  
It provides the Linux kernel release.

## Q4. Why did you use `bash -x`?

**Answer:**  
It allows the execution of Bash commands to be traced, making it easier to identify where unexpected behavior occurs.

## Q5. What happened with `uname -r`?

**Answer:**  
An issue was identified during debugging. The relevant implementation was corrected and made more stable, then tested again.

## Q6. Did the fix create any additional errors?

**Answer:**  
No further errors were found during the testing performed after the correction.

## Q7. Does finding a SUID file mean there is a vulnerability?

**Answer:**  
No. A SUID file is an enumeration finding. Whether it creates a security problem depends on the specific binary, permissions, configuration, and context.

## Q8. Why create a report function?

**Answer:**  
It combines information from multiple project modules into one text file, making the collected information easier to save and review.

## Q9. Why check whether `systemctl` exists?

**Answer:**  
Because a Bash script should not blindly assume that every command is available in every environment.

## Q10. Why is documentation part of the project?

**Answer:**  
Documentation records what was actually implemented, what was tested, what was corrected, and what remains to be done.
